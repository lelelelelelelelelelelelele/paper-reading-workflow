# 批判清单 + 评判轴

挑漏洞、判公平性、区分真算法 vs pipeline 装饰时逐条过。原则：挑真问题，不为批判而批判；论文没写清的直接说"论文此处不清楚"。

## 第零步：开炮前先核实消融实际测了什么（铁律）

**评判轴对 ≠ 可以不看证据就开炮。** 提"缺 baseline / 缺对照 / 归因不干净"这类指控前，必须先在正文/附录里搜一遍它的消融和 baseline 表，确认那个对照真的不存在。

- 常见翻车：把"selection vs random"误当成"有没有对照"。如果它有 Random Selection 一臂（且数据量/compute 与主方法一致），那"涨点是方法还是单纯多喂数据/多花 compute"这个问题它已经回答了——别再写"缺干净 baseline"。
- 动作：搜 `ablation` / `baseline` / `random` / `w/o` / `without` / `from scratch` / `full data`，把它的对照矩阵列出来，再判哪个变量没控住。
- 指控要落到"它没控住的那个具体变量"，不是泛泛说"对照不干净"。控住了就老实承认消融扎实，把火力收敛到真没做的地方（常见是 scale、范式对比、敏感性消融）。

---

## 第一步：定对评判轴（最重要，错了全错）

**先问这篇是什么品类，再决定拿什么去比。**

- VLM（无 action head）/ VLA（有 action，真机或仿真）/ 数据-curation 方法 / 训练范式 / 推理加速 —— 不同品类不同league。
- **不要用绝对性能榜判一篇方法/数据论文的死活。** 一个"数据筛选器"绝对分比不过"喂了海量真机数据的大 VLA"，是预期内的，不是死刑。
- 正确的轴是 **controlled gain（受控增益）**：同 backbone、同下游任务，用它的方法 vs 不用 / 随机 / 全量，涨了多少。efficiency / alignment 的 claim 用受控对比验，不用 leaderboard 名次验。
- 一句话模板：「它证明了 X 比不做 X 好，但有没有证明 X 比别的范式好？有没有证明 X 在更大模型上还好？」

## 第二步：逐条挑漏洞

### 基线公平性
- 自己跑的模型和 off-the-shelf 对比，**样本量 / 训练预算 / 参数量是否对齐**？有没有"受限预算下"才成立的结论被写成无条件 SOTA？
- 有没有最朴素的 baseline（同 backbone 直接微调、不做任何 trick）？涨点到底是方法的功劳还是多过一遍数据 / 多花 compute？
- 对标面是否太窄——是不是只挑一两篇好打的对手，回避了真正的竞争范式？

### 方法 novelty
- 哪步是真算法 / 真问题转化，哪步是 LLM 调用 + if-else + pipeline 装饰？
- 公式是不是"装饰术"——写得有概率论/理论深度，实际内核就是个加权平均 / 单调变换 / cleanup code？信号是否同源（换个形式包了同一个量）？
- 系数（α/β/γ、阈值、早停点）是不是拍脑袋定的，有没有敏感性消融？

### 实验说服力
- ablation 是否充分，有没有把"承重模块"单独拎出来测？最关键的那个组件去掉后掉多少？
- 有没有反常数字被一句话搪塞过去（"exhibit degraded performance"）？
- 可视化（t-SNE / cosine 图）是被当插图还是被当定量证据用？簇间距/簇大小有没有定量意义？定量该靠 MMD / 数值指标。
- 图表里的数从哪来，能不能对上正文 claim？

### scale / 泛化
- 增量随模型变大是缩水还是保持？有没有 7B+ / 真机的真空区？
- 全仿真还是有真机？real-world 是 demo 级（几个 episode）还是正经评测？
- cross-backbone / cross-domain 迁移有没有验，说明信号是内在属性还是单一特征空间产物？

### 结论 overclaim
- 摘要的 claim 有没有把成立前提（小模型/小预算/特定数据池）收敛进去？
- 理论最优性（如 GAN 判别器结论）和工程实现（轻量分类器 + 早停，没到最优）之间的缝，作者怎么圆的，圆得住吗？
- 循环论证 / 信息泄漏嫌疑：用下游分布去选预训练数据，会不会变相朝评测过拟合？

## 第三步：转成对自己有用的东西

- 这篇属于哪条压缩/聚合路径：selection（选数据）/ distillation（蒸模型）/ co-train（一起炼）/ 推理优化？
- 它的哪个测量法 / 框架 / 对照系可以借来量化自己的 idea？（拿走方法论，不是数字）
- 它哪个结论可以被自己的研究直接反驳或当对照基线？用 [[wikilink]] 钉到自己的 idea 笔记。

---

## 语气

像 Reviewer #2 但专业：尖锐、具体、可落地。每条批判要能指出「缺了哪个实验 / 哪个对比 / 哪个定义」，而不是空泛说"不够好"。给用户自己看的版本用平实口语，少加粗少口号。
